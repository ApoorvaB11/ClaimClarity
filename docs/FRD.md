# ClaimClarity: Functional Requirements Document (FRD) v2

Oct 12, 2026 · Apoorva Bhardwaj

## 1. System overview and data specification

ClaimClarity v2 is one self-contained web page. The 600 synthetic claims and a sample 835 file are embedded in it. Reading, grouping, charts, summaries and export all run in the browser. There is no server, database, login or saved state, and nothing a user loads leaves the browser. This document specifies that build and traces each requirement to the BRD v2.

| Item | Specification |
| --- | --- |
| Delivery | Single HTML page published as a Claude artifact, version 3 |
| Logic | Plain JavaScript, no libraries |
| Charts | Inline SVG: outcome donut, category bars, monthly trend line |
| Optional features | Claude summary rewrite and CSV download, both on the viewer's permission |
| Themes | Light and dark, following the viewer's setting |
| State | Filters, search, page and the loaded file held in memory; reset on reload |

**Demo data.** 600 records generated by a script (seed 42), all synthetic. Remittance dates run 2026-01-01 to 2026-10-30; service dates 2025-11-27 to 2026-10-20, 7 to 40 days before remittance. There are 5 fictional payers, 9 specialties and 15 procedure codes.

| Field | Type | Notes |
| --- | --- | --- |
| claim\_id, member\_id | text | CLM-000001 to CLM-000600; random member ids |
| payer, provider\_specialty, place\_of\_service | text | A specialty bills only plausible procedures at plausible places, for example a lab specialty only at a lab |
| service\_date, remittance\_date | date | ISO format |
| cpt\_code, cpt\_description | text | Short service labels written by the author |
| billed\_amount | number | USD, within a typical range for the procedure |
| status | text | Paid in Full, Partially Paid / Adjusted, or Denied |
| carc\_code, rarc\_code | text | Empty when paid in full; a remark code appears only where X12 rules or plausibility call for one |
| allowed\_amount, paid\_amount, patient\_responsibility | number | Zero on denied claims |

**Resulting mix:** 494 paid in full, 50 partially paid, 56 denied (9.3%). Duplicate and Timely Filing reasons appear only on whole-claim denials. Partial payments carry only Coding/Billing, Non-Covered or Missing Authorization reasons. Category and wording are looked up from the code, not stored in the record.

## 3. Code reference and category mapping

The X12 wording is quoted from the code lists on [x12.org](https://x12.org/codes/claim-adjustment-reason-codes) ([remark codes](https://x12.org/codes/remittance-advice-remark-codes)), read on 2026-10-12. The plain-English lines and the category are the author's. The category mapping is illustrative and is not an industry standard. For CARC 125 the quoted text is the portion read; the list may continue after it.

**CARC (claim adjustment reason codes)**

| Code | X12 wording | Plain English | Category |
| --- | --- | --- | --- |
| 4 | The procedure code is inconsistent with the modifier used. | The procedure code does not fit the modifier used. | Coding/Billing Error |
| 11 | The diagnosis is inconsistent with the procedure. | The diagnosis on the claim does not fit the procedure billed. | Coding/Billing Error |
| 15 | The authorization number is missing, invalid, or does not apply to the billed services or provider. | The authorization number is missing, invalid, or does not match the billed service or provider. | Missing Authorization |
| 16 | Claim/service lacks information or has submission/billing error(s). | The claim is missing information or has a billing error. | Coding/Billing Error |
| 18 | Exact duplicate claim/service (Use only with Group Code OA except where state workers' compensation regulations requires CO) | The payer already has this exact claim or service. | Duplicate Claim |
| 29 | The time limit for filing has expired. | The claim reached the payer after its filing deadline. | Timely Filing |
| 49 | This is a non-covered service because it is a routine/preventive exam or a diagnostic/screening procedure done in conjunction with a routine/preventive exam. | A routine or preventive exam, or a screening or diagnostic test done with one, is not covered. | Non-Covered Service |
| 50 | These are non-covered services because this is not deemed a 'medical necessity' by the payer. | The payer did not consider the service medically necessary. | Non-Covered Service |
| 125 | Submission/billing error(s). At least one Remark Code must be provided | A submission or billing error. The remark code gives the specifics. | Coding/Billing Error |
| 197 | Precertification/authorization/notification/pre-treatment absent. | The required pre-approval was not on file. | Missing Authorization |
| 198 | Precertification/notification/authorization/pre-treatment exceeded. | The service went beyond what the pre-approval allowed. | Missing Authorization |

**RARC (remittance advice remark codes)**

| Code | X12 wording | Plain English |
| --- | --- | --- |
| M51 | Missing/incomplete/invalid procedure code(s). | A procedure code is missing, incomplete or invalid. |
| M86 | Service denied because payment already made for same/similar procedure within set time frame. | The payer already paid for the same or a similar procedure within its set time frame. |
| MA63 | Missing/incomplete/invalid principal diagnosis. | The principal diagnosis is missing, incomplete or invalid. |

Any other CARC places the claim in Other / Unmapped and shows that the code is not in the reference set. Codes removed from v1 and why are in the BRD, section 6.

## 4. 835 reading rules, status logic and calculations

**File checks.** The file must start with an ISA segment of 106 characters, from which the element separator (position 4), sub-element separator (position 105) and segment terminator (position 106) are read. It must contain ST\*835. It must be under 2 MB and holds at most 5,000 claims; extra claims are ignored with a warning. Files with no CLP segment are refused.

| Segment | What the tool reads |
| --- | --- |
| BPR (element 16) | Payment date, used as the remittance date |
| N1 with qualifier PR | Payer name |
| CLP | Patient control number as claim ID, status code, charge, paid amount, patient responsibility, facility type |
| CAS | Group code and every reason code with its amount, up to six per segment |
| NM1 with qualifier QC | Member ID (element 9) |
| DTM 232, then 472 | Service date, in that order of preference; falls back to the payment date |
| SVC | Procedure code from the first service line |
| LQ with qualifier HE, and MOA | Remark codes; the first one is shown |

Specialty is not in an 835, so it shows Not in 835. A claim with status code 22 (reversal) is skipped with a warning.

**Status and reason rules**

1. CO-45 and PR-1, PR-2 and PR-3 are routine adjustments and are ignored when deciding status and reason
2. CLP status 4 gives Denied
3. Otherwise, any other adjustment gives Partially Paid / Adjusted
4. Otherwise the claim is Paid in Full
5. The reason is the first adjustment not ignored; its category comes from the mapping in section 3
6. Allowed amount is paid plus patient responsibility; it is zero on a denied claim

**Calculations, over the claims in view**

| Measure | Rule |
| --- | --- |
| Denial rate | Denied claims divided by claims in view. Partially paid claims are not counted as denied |
| Average days to remit | Mean of remittance date minus service date, in whole days |
| Monthly denial rate | Denied divided by all claims remitted that month, for every month from first to last in the loaded data; empty months are gaps |
| Category count | Claims with a reason, so partially paid claims count as well as denied ones |
| Trend axis top | The larger of 20% and the highest monthly rate, rounded up to the next 5 |

**Summary text.** Built only from computed figures: claim, denied and partially paid counts; the largest category; first, last and highest monthly rate; denied billed amount against total billed; and the payer with the highest denial rate among payers with at least 10 claims. The Claude rewrite is accepted only if every number in it appears in those figures and it contains none of: appeal, resubmit, should, recommend, advise, suggest, must, need to, consider.

## 6. Known limitations and traceability

**Limitations**

- Only 14 codes have translations. Every other code is shown as Other / Unmapped with no wording
- The category mapping and the routine-adjustment rule (CO-45, PR-1 to PR-3) are the author's, not industry standards
- The 835 reader was tested only on a hand-built sample. It reads one service line's procedure code per claim and shows only the first reason and first remark code
- Only the first adjustment that is not routine decides a claim's reason, even if a claim carries several
- The Claude rewrite guard checks numbers and advice wording only. A sentence with no numbers that is untrue or odd would not be caught
- Demo payers, members and amounts are invented; denial patterns in the demo are not drawn from real data
- The CSV download needs the viewer's confirmation and does not work in every view; copy to clipboard is the fallback
